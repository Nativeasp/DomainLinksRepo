⚙️ DomainLinks Backend – Python Services

The back-end of the DomainLinks application is implemented in Python, providing robust data processing, AI integration, and API services.

✨ Backend Highlights

  • FastAPI Framework - Modern, high-performance RESTful API server
  • Async Operations - Non-blocking I/O for scalable performance
  • AI Integration - Ollama LLMs and ChromaDB vector storage
  • Enterprise Database - SQL Server with SQLAlchemy ORM

🔑 Key Features

  • FastAPI v0.115+ RESTful APIs for communication with the front-end
  • Ollama AI/ML integration with local LLM models
  • ChromaDB Vector storage for RAG pipelines
  • SQLAlchemy SQL Server database access (v2.0+)
  • AsyncIO Background task processing with async operations
  • PyPDF2 / OCR PDF and Image processing via Windows OCR
  • HTTPX HTTP client for external API calls (v0.27.0+)
  • Pytest Automated testing with coverage reporting (v8.3.0+)

🌐 API Endpoints

POST /domains – Create new domain entities
POST /collections – Create new collections within domains
POST /documents – Upload and process text documents
POST /ask – Submit queries to the AI model with context retrieval
POST /ask/stream – Real-time streaming response for chat UI
POST /ask/context-preview – Estimate token budget before querying
GET /collections – List all collections
GET /domains – List all domains
POST /chat-backup – Manage chat backup files

📊 Database Schema

The backend uses SQL Server with 28 tables organized into logical groups:

Core Domain Tables

  • Domains (11 columns) - Main domain entities with metadata
  • Collections (8 columns) - Collections within domains
  • Documents (10 columns) - Uploaded documents and their content
  • DomainTypes (14 columns) - Domain type definitions
  • DomainControls (8 columns) - Domain control configurations
  • DomainOrientations (9 columns) - Domain orientation settings

Policy & Governance Tables

  • Policies (16 columns) - Policy definitions and metadata
  • PolicyPrinciples (7 columns) - Policy principle statements
  • PolicyObjectives (7 columns) - Policy objectives
  • PolicyControlStatements (9 columns) - Control statement definitions
  • PolicyConsequences (7 columns) - Consequence definitions
  • PolicyAccountabilityStatements (7 columns) - Accountability tracking
  • PolicyStrategyStatements (7 columns) - Strategy statements
  • PolicyTransparencyStatements (7 columns) - Transparency requirements
  • PolicyTemplates (9 columns) - Policy template definitions
  • PolicySections (8 columns) - Section organization
  • PolicyPrincipleLinks (7 columns) - Principle relationships
  • Principles (15 columns) - Core principle definitions
  • PrincipleRelations (7 columns) - Principle relationship mappings

Content & Retrieval Tables

  • ContentUnits (11 columns) - Content unit entities
  • ContentUnitEmbeddings768 (6 columns) - Vector embeddings for content
  • RetrievalProfiles (12 columns) - Retrieval configuration profiles
  • EmbeddingProfiles (10 columns) - Embedding model configurations

Reference & Configuration Tables

  • Controls (11 columns) - Control type definitions
  • ControlTypes (11 columns) - Control categorization
  • ProviderSettings (6 columns) - External provider configurations
  • SchemaMigrations (2 columns) - Database migration tracking

📦 Deployment

The back-end can be deployed as a standalone Python service or hosted on cloud platforms (AWS, Azure, GCP). It supports both local development and production environments with environment-based configuration.

Key Source Files

  • main.py – Application entry point and API server setup
  • app/ – Core application modules including domain logic and services
  • migrations/ – Database schema migrations using Alembic
  • tests/ – Unit and integration tests for backend components

Configuration

The project is managed with a pyproject.toml configuration file, which defines dependencies and build settings. It can be run directly via Python.

🔧 Development Workflow

  1. Install dependencies: pip install -r requirements.txt
  2. Configure environment variables in .env
  3. Run database migrations: alembic upgrade head
  4. Start the server: uvicorn main:app --reload
  5. Access API docs at /docs
